# 玻璃面板：透明、圆角、投影 —— 原理与踩坑总结

> 适用对象：`cmd/baozi` 里的三块玻璃（启动面板、设置窗、文件互传窗）。
> 主要文件：`glass.go`（抓屏 / 磨砂 / 配色 / 投影参数）、`backing.go`（底图合成 / 形状 / 平移）、
> `pane.go`（三块玻璃共用的状态与算法）、`subglass.go` + `subfollow.go` + `subdrag.go`（子窗独有部分）、
> `internal/win/shadow.go`（自绘投影层）。
>
> 这份文档只写"已被实测钉住的结论"，不写推测。凡是标了数字的地方，都是日志或取样量出来的。

---

## 0. 一句话总览

面板不是"半透明窗口 + 圆角"，而是**一张自己画好的整窗位图 + 一个自己画的投影层**：

- 圆角、抗锯齿、弧外的桌面、1px 边框，全在**同一张底图**里，一个像素只有一处来源；
- 投影是**另一块 layered 窗口**，按宿主的位置、尺寸、圆角半径现场算一张带 alpha 的位图；
- 窗口本身不再设 `SetWindowRgn` 区域（`bakedPanel = true`），形状完全靠底图的 alpha。

三块玻璃共用一份 `paneState`（`pane.go`），差异只剩两个回调：`spec`（投影位图参数）和 `gate`（投影该不该露面）。

## 1. 体系结构

### 1.1 每块玻璃其实是三个窗口

| 窗口 | 类名 | 干什么 | 关键样式 |
| --- | --- | --- | --- |
| 宿主（顶层） | `MyGoWindow` | 接鼠标、定位置尺寸、窗口矩形是投影的参照 | 面板 `ex=0x00200188`（TOPMOST/TOOLWINDOW/NOREDIRECTION）；子窗 `ex=0x00200100`（**非** topmost） |
| 内容子窗 | `MyGoSurface` | **真正画像素的是它**（DirectComposition 合成表面） | 系统拖动、截图排除、设区域对它都不太好使 |
| 投影层 | `BaoziShadowWnd` | 独立 layered 窗口，`UpdateLayeredWindow` 交位图 | `WS_EX_LAYERED\|NOACTIVATE\|TOOLWINDOW`，鼠标穿透靠 `WM_NCHITTEST` 回 `HTTRANSPARENT` |

三条由此推出来的事实，后面一半的坑都归到这三条：

1. **截图排除（`WDA_EXCLUDEFROMCAPTURE`）只对顶层窗口生效**，`MyGoSurface` 子窗一律被系统拒绝（日志形如 `抓屏排除自家窗口 3/6`）。而真正上屏的是子窗 —— 所以"排除自己"这条路从根上就不成立。
2. **`IsWindowVisible` 在这类合成窗口上会撒谎**（实测窗口明明在合成，查询返回 false）。可见性只能自己记账。
3. **投影层不会跟着宿主走**：独立窗口，位置、显隐、z 序都得由宿主状态驱动。

### 1.2 坐标系（混用一次就会错位）

| 概念 | 谁在用 | 单位 |
| --- | --- | --- |
| 窗口矩形 | 投影的参照矩形（`Place` / `Nudge` 的 x,y, w,h） | 物理像素 |
| 客户区 | 底图尺寸（`ClientRectPixels`） | 物理像素 |
| 底图 | 客户区 **+ 四周各 1px**（`backingPad`） | 物理像素 |
| 磨砂图 | 整屏的 1/4（`glassStep = 4`） | 物理像素的 1/4 |
| 桌面快照 | 整屏的 1/2（`deskHalfStep = 2`） | 物理像素的 1/2 |
| DIP | 所有"给人看的参数"（圆角半径、投影扩散、图标尺寸） | DIP × `glassScale()` = 物理像素 |

**底图里的 (inset, inset) 才是客户区的 (0,0)**。合成时所有采样原点都要把这一圈内边距挪回去（`gox/goy/dox/doy`），漏了就整张图偏 1px —— 表现是"最上面一行露出纯白"。

### 1.3 一块玻璃的全部状态（`paneState`）

```go
paneState{
  win, name, ap
  back        // 上屏用的底图（*ui.Bitmap）
  pix         // 合成用的复用缓冲（*image.RGBA），避免每帧新建
  pw, ph      // 底图尺寸（含 padding）
  key, keySet // 形状键：见 §3.2
  cx, cy      // 这张底图"取景"时的客户区原点（屏幕坐标，物理像素）
  bakAt       // 上次整张重烘的时刻（节流）
  shadow      // 这一层的投影层
  visible     // 我们想让它显示吗
  hostShown   // 系统那边确实显示着吗（由 WM_SHOWWINDOW 维护）
  spec        // 投影位图参数（差异点 1）
  gate        // 投影该不该显示（差异点 2）
}
```

方法：`keyAt / bakeAt / placeShadow / hideShadow / followShadow(light) / shouldShowShadow / hwnd / bitmap / prefix`。

## 2. 像素管线：从桌面到玻璃

```
                     ┌─ deskHalf（1/2 整屏，弧外"桌面"的采样源）
抓屏 CaptureScreenScaled ┤
                     └─ frostBase（1/4 整屏，留一张**没动过**的底片）
                               │
                    frostImage │ Blur(半径 5~12，拖动时 24~34) → Tint(压白 22,22,26 或 247,248,252)
                               ├─→ frostSmall  ← 合成底图时的采样源（1/4 分辨率）
                               └─→ frost       ← 给 UI 层当纹理用（整屏 DIP 尺寸）
                                             │
              composeBackingInto（逐像素，按圆角矩形的有符号距离算覆盖率）
                                             │
                         底图（客户区 + 1px，RGBA，形状外 alpha=0）
                                             │
                     ui.NewBitmap / Update → 铺满客户区（一张图铺整个窗口）
```

投影独立一条线：

```
Place(hwnd, ShadowSpec{位置, 尺寸, 半径, 扩散, 颜色…})
   → 只算"边带"（直边一列/一行共用一个 alpha，四角逐点算 SDF）
   → alpha = maxAlpha × (1 - d/m)³，贴着边缘 6px 用 smoothstep 起坡
   → UpdateLayeredWindow（BGRA 预乘）
   → SetWindowPos 到宿主所在 z 带
```

### 2.1 底图合成规则（`composeBackingInto`）

对每个像素算圆角矩形的有符号距离 `sd`（负=里面）：

| 情况 | 取色 |
| --- | --- |
| `sd > 1.2`（完全在形状外） | `alpha = 0`，交给 DWM 透出真背景（`alphaBacking` 默认开）；否则铺 deskHalf 的桌面像素 |
| `-1.2 < sd < 1.2`（贴边界一圈） | **4×4 超采样**数覆盖率 `cOut`；边框带覆盖率 `ringC` 单独数（只数"边界往里 1px"的子格） |
| `sd < -1.2`（内部） | 直接最近邻取磨砂图（磨砂图本身已在 1/4 分辨率上糊过，放大看不出差别） |

- 边框线默认**不画**（`ringMode = 0`），只有超采样出来的抗锯齿本身；
- 内部快路径用最近邻 + 预计算的列权重，是这个循环从 ~22ms 降到 ~9ms 的关键；
- 判定"要不要精确覆盖率"只看 `(x, y)`，**与窗口位置无关** —— 这是"平移快路径"能成立的前提（§4.1）。

### 2.2 参数映射（设置页 → 屏幕）

| 设置 | 范围/缺省 | 落到哪 |
| --- | --- | --- |
| 圆角 | 缺省 24 DIP，0~40（`DefaultPanelRadius` / `MaxPanelRadius`） | `glassRadius`（物理像素 = DIP × scale）；`glassClipRadius = r-1` 给内容层 |
| 透明度 | 缺省 59%，0~100 | 压白 alpha：0%→255，59%→158，100%→62；模糊：0%→12，59%→9，100%→5 |
| 投影 | 缺省 57%，0~100 | `win.SetShadowAlpha(pct/100 × 0.6)`；扩散固定 16 DIP（`ShadowMargin`） |

这些量**都是绘制时现读**，改完不需要重建窗口，但必须"重做磨砂图 + 重烘底图 + 重画投影"三件事一起做（见 §6.2 第 28 条）。

## 3. 三条铁律

写这三条之前踩了二十多个坑，回头看每一条都对应一串事故。

### 3.1 一个像素只能有一处来源

早期圆角是三层拼的：`SetWindowRgn` 切形状 + 四角月牙位图补弧外桌面色 + 投影层再补一遍弧。三层各按各的算法，交界处永远有缝：

- 弧和直边差一档 → "扇形的两个直边"；
- 弧外铺的色比真桌面偏一两档 → "鼓出去一点"；
- 区域那道 **1 位硬边**在弧上留台阶 → "毛边"。

结论：**形状、抗锯齿、弧外背景、边框全部并进一张底图**，区域、月牙、补色一律退出形状（`bakedPanel = true`、`SkipPatch = true`）。

### 3.2 形状变了必须进形状键

`backKey` 是"这张底图对应的形状状态"，少一个字段就等于"条件变了还吃旧图"：

```go
type backKey struct {
    cw, ch int          // 客户区尺寸
    r      int          // 圆角半径（物理像素）
    screenGen int       // 抓屏代次（换了桌面快照，桌面像素就过期）
    frost     int       // 磨砂图代次（透明度/模糊变了，玻璃像素就过期）
    dark      bool      // 桌面明暗（换配色，兜底色和字色都变）
    fade      bool      // 拖动糊化状态（糊度变了，每个像素的来源都变）
}
```

历史上漏过两个：`fade`（拖动开始/结束不重烘 → 一半清晰一半糊）、`frost`（改透明度保存后一个像素都不变）。

`frostGen` 由一个统一的位置自增：`frostFromScaled` 和 `rebuildFrost` 每重做一次磨砂图就 +1。这样"磨砂图换了"和"底图要重烘"是同一件事，结构上不可能各说各话。

### 3.3 投影层的生死、层次、位置都由宿主状态驱动

投影是独立窗口，它不知道宿主怎么了。三件事必须每次都问：

- **该不该露面**：`gate`（子窗 = `visible && hostShown`，面板 = `nil`，由 `hidePanel` 显式收）；
- **落在哪一带**：跟宿主同带（宿主是顶层窗口就保持 TOPMOST，普通带就 `HWND_NOTOPMOST`），
  并且**紧贴宿主上方**（插到"当前宿主上面那个窗口"的后面）。不落到那一带的最前，
  否则有别的置顶窗口盖住宿主时，这一圈影会浮在人家上面；也不能放到宿主下面，
  宿主切了圆角区域之后 DWM 不透出下层分层窗口，影整圈看不见；
- **位置对不对**：宿主一挪就 `Nudge`（拖动中，只 `SetWindowPos`）或 `Move`（程序自己摆窗口）。

## 4. 圆角与底图的坑

### 4.1 平移快路径：为什么能"只挪内容"

拖动时窗口每帧都在动，整张重烘（1100×660 约 9ms）会掉帧。做法：

1. 形状键没变 → 把旧底图内容整体 `shiftPix(dx, dy)`；
2. **然后必须重算四条带 + 四角**（`repaintBandsInto`）；
3. `Update` 同一张纹理。

- 带宽度是 `3+|d|`（只覆盖"边界过渡"+"被搬进内部的旧边界像素"+"新露出的桌面"），不是 `r+4`；
- 四角要重算的是 `(r+2+|d|)` 见方 —— 老角块被搬进来落下的那块也得盖掉；
- 位移超过四成尺寸时直接走整张（省得算的比整张还多）。

**坑 A：平移之后不补带 → 贴边一条亮线跟着窗口跑。**
`SetWindowRgn` 时代那条带是"区域外的桌面"，整窗自绘后是"按旧坐标算出来的 alpha=0 和覆盖率"。子窗抽象时只做了 `shiftPix + Update`，于是深色桌面上一条亮线跟着窗跑。

### 4.2 抗锯齿：从"中心距离"改成"数面积"

直边上"离边界 0.5px 内线性过渡"是对的（覆盖率只跟一个坐标有关）；但弧上一个像素里转十几度，中心距离推不出覆盖面积 → 每个像素差一两档，排成能数出来的台阶。

现在：`|sd| < 1.2` 的像素做 **4×4 超采样**，覆盖率 = 数出来的子格比例；边框带也是单独数 `r16`，而不是 `cOut - cIn`（后者在 45° 弧上只有七成，于是"直边是实线、弧上是虚线"）。

### 4.3 半径不能减内边距

```go
// 错：r := radius - inset   → 角比直边多收 1px，切点处露台阶
// 对：形状整体往里挪 inset，半径不变
r := radius
```

### 4.4 半像素与"边框内部还有一条线"

窗口 DIP → 物理像素不是整数（例如 909 DIP × 1.25 = 1136.25）：右边、下边的最后一格只盖住 0.25 格，内容层的覆盖率被 DWM 补成白色 → 右侧 `#FCFDFF`、下侧 `#FFFFFF`，看着像"边框里面还有一条线"。

两处修法：

- 投影层里最外一圈像素按**整数物理像素**布局，涂成"玻璃色"（按四角 → 边中点两段插值，避免出现一条偏灰的线）；
- 阴影中心用 `(w-1)/2` 而不是 `w/2` —— 差半格会让右边/下边第一格落在"零"上，露出一条 1px 亮线（实测右 `#F5F5F5`、下 `#FFFFFF`，左 `#A3A3A3`）。

### 4.5 弧不能"鼓出去"

弧带斜坡只往**弧内**展开（`t` 从 1 到 0，弧外一律桌面色）。只要往弧外铺一格，屏幕上就是"圆弧比边框鼓出一圈"。

### 4.6 给子窗设区域会制造死区

`SetWindowRgn` 是真的改变窗口形状，不只是画法：区域外的鼠标事件不属于这个窗口，UI 层连 pointer down 都收不到。给 `MyGoSurface` 套圆角区域，四个角就成了"按下去毫无反应"的死区 —— 尤其右下角，正好是拖面板时手最容易落下的地方（实测各边中点都能拖，只有 `(w-25, h-25)` 拖不动）。

结论：区域只设顶层，且整窗自绘之后连顶层也不设。

### 4.7 拖动时四角变方

静止时四角由投影层补，可拖动时投影层是收起的 —— 那时只剩区域那道 1 位硬边，弧上一格一格，右下两条边还在动，台阶一眼看见。所以拖动期间由面板自己把四角画出来（`UseCornerBitmaps` 那一套），且只在唤出时造图（造完要整屏重绘 ~40ms，放在"缩放松手"那帧就是卡顿）。

## 5. 投影的坑

### 5.1 Win10 上"有区域就没 DWM 影"

逐条实测：空闲（区域在）时窗口外侧整条带全是桌面底色；拖动/缩放那一瞬间（区域被撤掉）才冒出 `#C7C7C7 → #FFFFFF` 一圈影；停手设回区域立刻消失。`DWMWA_NCRENDERING_POLICY=ENABLED`、`DwmExtendFrameIntoClientArea(1px)` 都返回成功，影依然不出来 —— 属性是真设上了，只是"有区域的窗口"在 DWM 里就是没有影。

而圆角和抗锯齿当年必须靠区域（Win10 没有别的圆角手段），所以**两者不能共存**，只能自己画。

### 5.2 自绘影垫在下面看不见

第一版把 layered 窗口垫在面板下面（z 序在下）：`UpdateLayeredWindow` 返回成功、位图 alpha 也有值，屏幕上却完全没有。原因是 DWM 对被区域裁剪的窗口下方那块分层窗口不做合成。

改成压在**上面**一层：面板内部那块的 alpha 恒为 0，所以面板本身一点不受影响；鼠标穿透由 `WM_NCHITTEST → HTTRANSPARENT` 兜住。

（顺带一个反例：不能带 `WS_EX_TRANSPARENT` —— 带它这块分层窗口在 Win10 上整片不合成。）

### 5.3 只有四角有影

```go
// 错：d := math.Hypot(qx, qy) - r        // qy 是负数时把 hypot 撑到几百
// 对：d := math.Sqrt(max(qx,0)² + max(qy,0)²) + min(max(qx,qy),0) - r
```

错的那版：直边上 d 直接冲到几百、alpha 全 0，只有两个轴都为正的四个角有影 —— 现象就是"只有角上有影，四条边光秃秃"。

### 5.4 底部一条直角硬边

阴影曾整体下移 `m/8` 模拟"光源在上"。代价：位图只比面板大 `m`，下移之后底边离参照矩形不到 `m`、alpha 不为 0，于是影在最下一行被**切断**，屏幕上是一道水平直角硬边（右下角最明显）。

改成**不偏移**：alpha 在 `d = m` 处正好归零，图层边缘天然干净。

### 5.5 紧贴边框的一条近黑线

面板最外圈是半覆盖的抗锯齿像素，压不住最浓的那圈阴影 → 紧贴边框一条近黑细线，换壁纸它还会跟着变色。

修法：最里面 6px 用 `smoothstep` 从 0 起坡，让阴影"离开边框一点再浓起来"。6px 相对 20px 的扩散宽度只是把最内一点压下去，整体观感不变。

### 5.6 空心的"投影框"（投影层浮在别人的窗口上）

症状：面板/设置窗被别的程序盖住以后，屏幕上还剩一个和它一样大、能透出下层内容、带边框和阴影的空壳，点它还没反应。

真因：`Place` 无条件 `SetWindowPos(hwndTopmost)`。面板本身是 TOPMOST，没问题；设置窗和互传窗是**普通窗口**（`ex=0x00200100`），宿主被盖住时，这一圈影还压在最顶层 —— 中间就透出下层窗口，看起来就是一个空框。

修法：**宿主的 z 带决定这一层的位置**，而且要贴在宿主身边，不能落在那一带的最前。宿主有 `WS_EX_TOPMOST` → 这一层也保持 TOPMOST；否则先 `HWND_NOTOPMOST` 摘掉自己的顶层标志。带对齐之后一律"紧贴宿主上方"：取 `GetWindow(host, GW_HWNDPREV)`（宿主上面那个窗口），把投影插到它的后面，z 序就成了 `[上面那个窗口, 投影, 宿主]`。宿主已经在自己那一带的最前时，落回那一带最前。

于是：面板被置顶窗口盖住时，投影跟着一起被盖住；面板被抬高时投影也还贴着它。`ShowWindow` 之后系统会把窗口塞回自己那一带的最前面，所以每次上屏都 `restack()` 一次（现算邻居，不用缓存的锚点）。

注意别学早期那版"把投影放到宿主下面"（`insertAfter=宿主`）：宿主用 `SetWindowRgn` 切了圆角之后，DWM 不再透出压在它下面的分层窗口，整圈影会彻底看不见（位图 alpha 有值、`UpdateLayeredWindow` 也成功，屏幕上却什么都没有）。

### 5.7 "面板藏了，影还在"

投影是独立窗口，宿主 `SW_HIDE` 不会连坐。三处门控都漏过：

- 宿主隐藏时 `refreshShadow` 还在按**旧矩形**摆位置 → 桌面上一个没人认领的空框；
- `followShadow` 在窗口已经不在了还在挪；
- 缓存里 `shown = true`，实际被系统/别的程序藏起来了 → `Show` 一直空转，四角桌面色再也不回来（屏幕上是"四个半透明的直角"）。

现在的做法：`visible && hostShown` 双门控（`hostShown` 由顶层收到 `WM_SHOWWINDOW(wparam=0)` 置 false），`Show/Hide` 都按**真实可见性**决定要不要 `ShowWindow`，`ForceShow` 干脆每次都调（这个调用本身幂等、成本可忽略）。

### 5.8 缩放时卡死、拖动延迟

- `GetDC` 没配 `ReleaseDC`：缩放每帧跑一次，几十帧就把进程 DC 池吃光，整个桌面卡住（用户实测"缩放时卡死"）。
- 每帧 `UpdateLayeredWindow` 重传整张影（一千多像素宽，十几毫秒）→ 拖动延迟。位图内容在拖动中并不变，改成 `Nudge`（只 `SetWindowPos`）。程序自己摆窗口才走 `Move`。
- 整张阴影逐点算 → 一次 `15~25ms`。改成"只算四条带"：直边上 alpha 只跟一个坐标有关，一行/一列一个值，只有四角逐点算。

## 6. 合成时序与"看起来该动却没动"的坑

### 6.1 拖动时面板和内容错位

`SetWindowPos` 和 DComp `commit` 落在相邻两帧，快速拖动时一帧内相对位移十几像素，靠玻璃里的桌面细节一眼就能看出错位。

两步：

1. 拖动时把磨砂图**糊透**（模糊 ×6，钳到 24~34）+ 压白加厚 44 —— "没有细节可比对就判不出错位"，面板仍是半透明玻璃，观感上还是跟着手走；
2. 再盖一块同形状的实心遮罩（`dragWhiteBitmap`，颜色跟桌面明暗走），彻底没有可比对的细节。

这是 Windows 自己拖毛玻璃窗口时退化成纯色的同一个思路。

### 6.2 那些"值改了、屏幕没改"的清单

| # | 症状 | 真因 | 修法 |
| --- | --- | --- | --- |
| 28 | 改透明度/模糊保存后一个像素都不变 | 磨砂图没进 `backKey`；且 `applyAppearanceNow` 只刷面板、面板藏着就 `return`；`frost.Update` 只换纹理没换 `frostSmall` | 加 `frostGen` 进键；重排刷新顺序；`rebuildFrost` 同时更新两份 |

### 6.3 子窗独有：表面被清、没人画回来

"按需推帧"（show / 挪位 / 拖完才 `FrameNow`）的代价：合成表面一旦被系统清掉，没有任何人把它画回来。实测点别的窗口让设置窗失活之后，窗口本体和投影都还在屏上（`IsWindowVisible` 都是 true、surface 尺寸也对），客户区却一个像素都不画 —— 屏幕上只剩"边框 + 阴影"的空框，点回去也点不动。

修法（`subfollow.go`）：

- `WM_ACTIVATE` / `WM_NCACTIVATE` → 重烘底图 + 重摆投影 + `FrameNow`；
- `WM_PAINT` / `WM_ERASEBKGND` → 只推帧，不重烘（`lastPush` 做 50ms 节流，防止连锁重绘）；
- `WM_SHOWWINDOW(0x0018)` wparam=0 → `hostShown = false` + 收投影 + 取消拖动。

### 6.4 系统拖动会把自绘窗口当矩形搬

顶栏用系统拖动（`WM_ENTERSIZEMOVE` 一串 `WM_MOVE`）时，四角立刻变直、alpha 全丢。所以三块玻璃的拖动都必须**自绘**（`dragwin.go` / `subdrag.go`）：自己跟鼠标、自己 `SetWindowPos`、自己重烘/平移、结束时清理（`wmCancelMode(0x1F)`、发现左键已松开就地 finish、阈值统一 6px）。

同时投影层要跟着走：`WM_MOVE` 是发给**顶层窗口**的（子窗口在父窗口移动时客户区坐标不变，收不到），所以 `WM_MOVE` 子类化必须挂在顶层句柄上。

### 6.5 抓屏抓到自己

- `WDA_EXCLUDEFROMCAPTURE` 只对顶层生效，子窗被拒 → 排除永远不完整；
- 真正画像素的是子窗 → 截图里永远能看到自己。

结构性解法：**自家窗口在屏上时干脆不抓**（`selfWindowOnScreen`），沿用上一张干净底片 —— 几何上仍然对得上屏幕，最多桌面内容旧一点。`excludeSelfCapture` 留着当保险。

同理，子窗 `ensureFrost` **不重新抓屏**：那时窗口已经显示出来了，重抓就是把自己糊进玻璃。

### 6.6 每帧都新建纹理

`ui.Image` 渲染一次就把纹理缓存住了：换 `Bitmap` 对象屏上不会变，必须 `Update` 像素。而每 `NewBitmap` 一张就是一条新 GPU 纹理，而且"每条都会留一会儿" —— 唤出几十次就攒一堆（内存上涨的其中一个来源）。

规则：**尺寸没变就 `Update`，变了才 `NewBitmap`**。

### 6.7 两套平行实现 = 必然会漏

面板的状态散在 `application` 上，子窗另有一份 `subGlass`，方法名一样、字段名不一样。于是"抽出来时漏一处"就漏一次观感问题：`backKey` 漏 `fade`、`shiftTo` 漏带状重绘、投影漏 `hostShown` 门控、投影 z 带没跟宿主。

现在统一到 `paneState`：形状键、平移、带重算、投影门控、z 带只有一份代码；两个差异点用 `spec` / `gate` 回调注入。**结构上不可能再分叉。**

## 7. 诊断工具箱

原则：**不信截图，只信自己喂给系统的数据。**

| 手段 | 环境变量 / 函数 | 用途 |
| --- | --- | --- |
| 导出底图 PNG | `BAOZI_BACKDUMP=<path>`（`bakeAt` 里） | 面板是 noRedirect 合成的，屏幕截图会被别的窗口干扰；量弧的覆盖率只能看这份原始数据 |
| 形状诊断配色 | `BAOZI_BACKTEST=1`（形状外红 / 边框带蓝 / 内部白） | 截图上直接量"形状铺到哪" |
| 逐行探针 | `BAOZI_ROWPROBE=1`（顶部四行洋红/青/黄/绿） | 判断"图偏了几个像素" |
| 投影位图导出 | `Shadow.DumpRGBA` / `DumpAlpha` | 分层窗口 `GetPixel` 拍不到，只能把"喂给 DWM 的东西"存成文件 |
| 无影 / 无补角 | `BAOZI_NOSHADOW=1` / `BAOZI_NOCORNER=1` | 对照：没有自绘层时四角到底有没有白 |
| 边框环老画法 | `BAOZI_RING=1/2` | 对比"白弧"是不是这条线 |
| 分段计时 | `BAOZI_BACKTIME=1` | 平移 shift / 重烘 / Update 各多少毫秒 |
| 像素取样 + 日志 | — | 用户报"看不出来"时，用取样点颜色 + 日志证明，不靠人眼 |

几条经验：

- **别用 `IsWindowVisible` 判断这类窗口**（会撒谎），也别用 `GetWindowRect` 判断隐藏窗口的位置（返回旧值）；
- 隐藏态尺寸是 `0x0@0,0`，别拿它当证据；
- 面板藏着时碰 `refreshShadow` 会按旧矩形在桌上摆一个空框 —— 门控里必须先看 `visible`；
- `composeBackingInto` 里 1100×660 一次 `22ms`，其中大半是每像素一次堆分配 —— 性能问题的第一嫌疑永远是"循环里分配"。

## 9. 一句话备忘

- 圆角不是"设个区域"，是**一张带 alpha 的图**；
- 投影不是"系统给的"，是**另一块窗口**，它的生死层次位置都得宿主管；
- 玻璃不是"半透明的窗口"，是**桌面快照的磨砂 + 压白**，所以它不会跟着视频动 —— 这是刻意的取舍（实时背景更新做过又被否决，代价是每帧抓屏）。
